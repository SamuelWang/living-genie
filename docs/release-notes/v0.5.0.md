# Release notes — v0.5.0

Living Genie's fifth release is for the person running it rather than a new feature for diary or
todo users: **operational visibility**. The backend and indexing worker now produce structured
logs, metrics, and distributed traces, and `docker compose up` brings along a self-hosted Grafana
stack to explore them. You can see how requests and background jobs are behaving, drill into a
slow or failing one, and jump from its trace to the logs it produced, all without an external
account and without any telemetry leaving your machine.

## What's new

- **Structured logs** — the backend and worker write JSON log lines, each tagged with the trace
  and span of the request or job that produced it. They're still printed to the console, and are
  now also searchable in Grafana.
- **Metrics** — request rate, error rate, and latency per API route; indexing jobs processed and
  their durations, split by diary entries and todos; and chat-specific numbers: how often Genie
  called each todo tool (and whether the call waited for your confirmation), and how long the
  retrieval search took.
- **End-to-end traces** — every request and indexing job is traced, including its database,
  vector store, and model calls, so you can see exactly where the time went.
- **Chat broken down step by step** — a chat reply's trace shows each stage separately: embedding
  your question, searching your diary and todos, building the prompt, each call to the model, and
  each todo action Genie took or held for your confirmation. What you and Genie wrote isn't
  recorded in these traces.
- **Indexing jobs broken down step by step** — a background indexing job's trace shows chunking,
  embedding, and saving to the vector store as separate steps; when a job fails, the trace
  highlights the step that failed.
- **Grafana, ready to go** — Prometheus, Loki, Tempo, and Grafana run alongside the rest of the
  app, with the data sources and a starter "Living Genie overview" dashboard already set up. Open
  Grafana at `http://localhost:3000` (default login `admin`/`admin`, configurable in `.env`).
  From any trace, "Related logs" jumps straight to the log lines it produced.
- **Configurable without code changes** — retention periods, where telemetry is sent, and the
  trace sampling rate are all set through environment variables.

## Not included yet

v0.5.0 doesn't include:

- hosted or SaaS observability backends (Grafana Cloud, Datadog, etc.); this release is
  self-hosted only
- alerts or notifications on metric thresholds; this release has dashboards only, and alerting is
  a likely near-term follow-up
- instrumentation of the web frontend
- a high-availability or clustered observability stack
- retention tuning beyond the configurable defaults
- product or usage analytics
- sampling beyond a single configurable rate
